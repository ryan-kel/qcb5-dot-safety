# QCB5 DOT Safety Infrastructure Analysis

This repository analyzes NYC DOT safety infrastructure request outcomes for Queens Community Board 5 (QCB5), using NYC Open Data sources for traffic signal/all-way stop studies, speed reducer requests, APS installations, and injury/fatal crash records.

## Setup

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m playwright install chromium  # only needed for export_map_png.py
```

## Reproduce Current Committed Outputs

```bash
source .venv/bin/activate
python generate_charts.py
python generate_maps.py
python scripts_validate_outputs.py
python -m unittest discover -s tests
```

This path uses the committed `data_raw/` snapshot. Do not run `scripts_fetch_data.py` first unless you are intentionally refreshing source data.

## Live Data Refresh

```bash
source .venv/bin/activate
python scripts_fetch_data.py
python generate_charts.py
python generate_maps.py
```

After a live refresh, review `data_raw/fetch_manifest.json`, `output/source_manifest.json`, raw row counts, generated tables, and public methodology text before replacing committed outputs. `scripts_validate_outputs.py` pins the current committed snapshot, so its expected raw counts and layer counts may need an explicit review/update after refreshed data changes.

`generate_maps.py` also writes `output/source_manifest.json` and rebuilds both `output/data_bundle_v1.0.zip` and root `data_bundle_v1.0.zip`.
`scripts_validate_outputs.py` checks raw counts, input schemas, curated provenance, geocode-cache parity, map-layer counts, map point geometry, proximity/map-layer joins, chart and table artifacts, calculated rates and percentages, source labels, manifest hashes, and data-bundle contents.

## Data Notes

- `output/data_cb5_signal_studies.csv` is a curated input, not generated by the scripts. Signal Studies lack a community-board field and source coordinates, so this file needs human-reviewable provenance before publication. `output/data_cb5_signal_studies_provenance.csv` is a row-level scaffold that covers every current curated row, checks each row against the committed citywide raw snapshot by `id` and `referencenumber`, and marks all rows as needing review. Current raw-match status: 495 matched rows, 3 duplicate raw matches for `CQ21-0749`, and 1 curated row (`CQ25-0457B`) missing from the committed raw snapshot.
- SRTS and crash records are filtered against `data_raw/cb5_boundary.geojson` after source-specific prefilters.
- `output/geocode_cache_signal_studies.csv` is synchronized to the current resolved non-APS signal-study universe before map generation. Rows that cannot be geocoded remain in the cache with blank coordinates instead of being silently dropped.
- `output/data_unmatched_signal_geocodes.csv` lists the current resolved non-APS signal-study rows that still lack an in-polygon local geocode and need manual review before they can appear in map/proximity outputs.
- `output/source_manifest.json` records the build timestamp, analysis window, row counts, file hashes, source URLs, planned Socrata query parameters, and provenance warnings for the current local snapshot.
- `scripts_fetch_data.py` writes `data_raw/fetch_manifest.json` during live refreshes, recording source metadata, per-dataset fetch timestamps, query clauses, stable Socrata `$order` fields, pagination, row counts, and output paths.
- Current committed outputs use the 2020-2025 analysis window. The scripts compute the end year dynamically as the last complete calendar year.
